# Real-browser test on Florian's laptop

Sandy has no GPU, so everything WebGPU-shaped was tested with a deterministic mock
provider. This is the checklist for the one thing only a real machine can prove: that a
browser actually loads Ternary Bonsai 2 27B onto a GPU and serves the swarm.

**Expected result on the 8 GB RTX 4060 laptop: ~2.1–2.7 tok/s, i.e. it FAILS admission
(the bar is 10 tok/s).** That is the correct outcome, not a bug — use the admin
override below to still exercise the whole path end to end.

## 0. Before you start

* Chrome (not Edge/Firefox) on Windows, WebGPU enabled — check `chrome://gpu`.
* ~6 GB free disk for the weights, ~10 GB free RAM.
* First run downloads 5.9 GB (≈15 min). A second run loads from IndexedDB in ~50 s.
* Sign in at https://bonsai-swarm.app.mintapis.com (anonymous username + password).

## 1. Provider, the plain way

1. Open https://bonsai-swarm.app.mintapis.com/share.html
2. Press **Start sharing**. Watch the activity log:
   * `Browser storage marked as persistent` — the weights survive a restart.
   * progress bar to 100 %, then `Model ready after …`.
   * `Measured X tokens/s` — **write this number down**, plus TTFT.
3. Expect: *"Too slow to serve other people — but your own chat still works."*
   Confirm the page says so and that `/api/stats` still shows `providersReady: 0`.

## 2. Provider with the admin override (functional test of the whole path)

The override admits a GPU below the bar. It needs either an admin account or the
server's `TEST_MODE_KEY`.

```
https://bonsai-swarm.app.mintapis.com/share.html?override=1
```

(as an admin account — otherwise append `&testKey=<TEST_MODE_KEY>`)

Then check, in this order:

- [ ] status goes to **Online** and the wallet chip starts ticking up after a minute
- [ ] `/api/stats` shows `providersReady: 1`
- [ ] in a **second browser profile** (or a private window with a second account):
      open `/chat.html`, ask something, and watch the answer stream in — it is being
      generated by the first browser
- [ ] the provider tab shows "Answering a request from the network…", then
      "Served a request: N tokens"
- [ ] coins fly into the wallet chip on the provider page (the animation)
- [ ] the consumer's message footer shows `−X AI Coins`
- [ ] `/wallet.html` on both accounts: the ledger has `serve_tokens` / `consume_tokens`
      rows with matching token counts, and the balances moved in opposite directions
- [ ] the provider's `/api/jobs` shows the job **without any prompt text**
- [ ] close the provider tab mid-answer once: the consumer should see
      "provider dropped — retrying" and, with no second GPU online, a friendly failure
      rather than a hang

## 3. Background behaviour

- [ ] with the provider tab in the background (another tab in front), a request still
      completes — this is what the Web Worker is for
- [ ] minimise the whole window: some systems still throttle; note what happens

## 4. The CLI client

```powershell
npx bonsai-swarm-client login          # token from /wallet.html
npx bonsai-swarm-client provide --override
```

- [ ] a Chrome window opens, loads the model, and the terminal prints live status
- [ ] in another terminal: `npx bonsai-swarm-client serve`, then
      `curl http://127.0.0.1:4777/v1/chat/completions -H "content-type: application/json" -d "{\"messages\":[{\"role\":\"user\",\"content\":\"hi\"}],\"stream\":true}"`
      streams an answer
- [ ] `npx bonsai-swarm-client ask "2+2"` prints an answer and the coins charged
